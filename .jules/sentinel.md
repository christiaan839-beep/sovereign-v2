## 2025-05-18 - [Fix Timing Attack Vulnerabilities in Webhook Signature Verification]
**Vulnerability:** Several webhook signature verification functions (`verifySignature` for PayFast, `verifyPayFastSignature`, and `verifyPaystackWebhook`) were comparing cryptographic hashes against user-provided signatures using standard string equality `===`. This allowed for potential timing attacks, where an attacker could deduce the correct signature by measuring the time taken for the comparison to fail.
**Learning:** String equality (`===`) checks in JS return `false` as soon as a character mismatch is found. When comparing cryptographic hashes, this creates a timing vulnerability. The vulnerability pattern was spread across both route handlers and utility libraries in the application handling payment webhooks.
**Prevention:** Always use `crypto.timingSafeEqual(bufferA, bufferB)` for comparing cryptographic hashes, MACs, or signatures. Furthermore, because `timingSafeEqual` throws a `RangeError` if the buffers are of unequal length (which can lead to denial-of-service or unhandled exceptions), always perform a length check (`bufferA.length === bufferB.length`) before calling `timingSafeEqual`.
