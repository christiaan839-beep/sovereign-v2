## 2024-07-24 - [CRITICAL/HIGH] Fix SSRF in audit agent
**Vulnerability:** The `audit` agent route (`src/app/api/_agents/audit/route.ts`) was using a bare `fetch()` to fetch user-supplied URLs, which could allow a Server-Side Request Forgery (SSRF) attack to probe internal network resources or cloud metadata endpoints.
**Learning:** Using a bare `fetch()` with user-controlled input circumvents our established egress policies and SSRF defenses. Even seemingly isolated tools need strict network boundary enforcement. Be extremely careful when adapting code to use `outboundFetch` instead of a standard `fetch` - the `response.body` is a `ReadableStream` while `response.text()` returns a promise for a string. Furthermore, always ensure the properties being used on the response object (`text()`, `body()`, etc) match the actual shape of the return object (`OutboundFetchResult` in this case where `body` is actually a `string`). Wait, no, `outboundFetch` returns `{ status: number, ok: boolean, url: string, contentType: string | null, headers: Record<string, string>, body: string, bytes: Uint8Array, truncated: boolean }` so `response.body` is a string! So using `response.body` here was actually correct.
**Prevention:** Always use `outboundFetch` from `@/lib/outbound-fetch` for any network requests initiated by user input. This helper automatically checks hostnames against allowlists and validates DNS resolution to block private IP spaces.
## 2023-10-27 - Replace Manual Constant-Time Comparison with Node's crypto.timingSafeEqual
**Vulnerability:** The webhook trigger and agent token validation code used a manual loop with `charCodeAt` and XOR for comparing string keys/signatures in constant time. This can be problematic and is not as safe as the native crypto implementations.
**Learning:** Manual implementation of `constantTimeEqual` logic using string length checking before converting strings to buffers is insufficient and allows attackers to trigger unhandled exceptions via `ERR_CRYPTO_TIMING_SAFE_EQUAL_LENGTH` in case of multi-byte UTF-8 or invalid hex characters. Node's `crypto.timingSafeEqual` provides guaranteed constant-time comparison. The memory file specifies: "When comparing cryptographic secrets with `crypto.timingSafeEqual`, always verify buffers are of equal byte length *after* converting strings to buffers (`bufA.length === bufB.length`). Checking string length before conversion is insufficient (e.g., multi-byte UTF-8, or invalid `hex` characters which truncate the buffer) and allows attackers to trigger unhandled exceptions (DoS) via `ERR_CRYPTO_TIMING_SAFE_EQUAL_LENGTH`." Also, "Replace custom manual constant-time string comparison loops (e.g., using bitwise XOR on `charCodeAt`) with Node.js native `crypto.timingSafeEqual` for cryptographic string comparisons. Ensure strings are first converted to Buffers and checked for byte length equality."
**Prevention:** Always use Node.js `crypto.timingSafeEqual` for secret verification after converting to Buffers and validating the byte lengths match.
