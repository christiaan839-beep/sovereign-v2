## 2024-07-24 - [CRITICAL/HIGH] Fix SSRF in audit agent
**Vulnerability:** The `audit` agent route (`src/app/api/_agents/audit/route.ts`) was using a bare `fetch()` to fetch user-supplied URLs, which could allow a Server-Side Request Forgery (SSRF) attack to probe internal network resources or cloud metadata endpoints.
**Learning:** Using a bare `fetch()` with user-controlled input circumvents our established egress policies and SSRF defenses. Even seemingly isolated tools need strict network boundary enforcement. Be extremely careful when adapting code to use `outboundFetch` instead of a standard `fetch` - the `response.body` is a `ReadableStream` while `response.text()` returns a promise for a string. Furthermore, always ensure the properties being used on the response object (`text()`, `body()`, etc) match the actual shape of the return object (`OutboundFetchResult` in this case where `body` is actually a `string`). Wait, no, `outboundFetch` returns `{ status: number, ok: boolean, url: string, contentType: string | null, headers: Record<string, string>, body: string, bytes: Uint8Array, truncated: boolean }` so `response.body` is a string! So using `response.body` here was actually correct.
**Prevention:** Always use `outboundFetch` from `@/lib/outbound-fetch` for any network requests initiated by user input. This helper automatically checks hostnames against allowlists and validates DNS resolution to block private IP spaces.
## 2025-02-12 - Prevent SSRF with outboundFetch
**Vulnerability:** Bare `fetch()` calls on user-provided URLs allow Server-Side Request Forgery (SSRF) and DNS rebinding attacks, exposing internal cloud metadata and RFC1918 addresses.
**Learning:** The previous custom SSRF regex blocking was insufficient. The repository provides `outboundFetch` from `@/lib/outbound-fetch` which does DNS-level resolution and checks against private IPs to securely block SSRF.
**Prevention:** Always use `outboundFetch` instead of bare `fetch()` when hitting arbitrary external URLs provided by user input, and handle its `OutboundFetchResult` accordingly.
