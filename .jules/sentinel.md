## 2024-05-12 - Replaced bitwise string comparison with crypto.timingSafeEqual
**Vulnerability:** Manual bitwise XOR comparison using `charCodeAt` for string equality (e.g., `a.charCodeAt(i) ^ b.charCodeAt(i)`) was used in security-critical contexts like `authenticateApiKey` in `src/app/api/_agents/trigger/route.ts` and `constantTimeEqual` in `src/lib/agent-tokens.ts`. This approach is error-prone, vulnerable to JS engine optimizations making it not truly constant-time, and doesn't handle multi-byte characters correctly.
**Learning:** Node's `crypto.timingSafeEqual` is the only safe way to do constant-time comparisons in Node.js. It requires both inputs to be Buffers or TypedArrays of the exact same length. Checking length equality string-side before Buffer conversion is unsafe for strings containing multi-byte characters (length in chars != length in bytes), leading to DoS crashes (`ERR_CRYPTO_TIMING_SAFE_EQUAL_LENGTH`).
**Prevention:** Always convert strings to Buffers first (`Buffer.from(str, 'utf8')`), then compare their `byteLength`, and finally use `crypto.timingSafeEqual`. Never use manual bitwise loops for security comparisons in JavaScript.
