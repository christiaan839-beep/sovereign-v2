
## 2026-08-26 - Keyboard Accessibility for Hover Actions in ScreenNode
**Learning:** Interactive icon-only buttons hidden behind CSS hover states (`opacity-0 group-hover:opacity-100`) become inaccessible to keyboard users. To make them accessible, the parent container must include `focus-within:opacity-100`. Furthermore, to provide clear visual feedback without showing focus rings on mouse clicks, utility and icon-only buttons require `focus-visible:ring-2`, `focus-visible:outline-none`, and `aria-hidden="true"` on the internal SVG icon element to prevent screen reader clutter.
**Action:** When creating action bars hidden on hover, always add `focus-within` to the parent container and `focus-visible` utility classes to the buttons to ensure clear focus indication for keyboard users.
## 2024-09-24 - Accessible Hover Actions for Interactive Elements
**Learning:** Actions hidden behind `group-hover:opacity-100` are invisible to keyboard users who tab through the interface. Furthermore, icon-only buttons need `aria-hidden="true"` on the internal SVG to avoid screen reader clutter while keeping the `aria-label` on the parent button. Lastly, custom focus rings must use `focus:outline-none` and explicit `focus-visible:ring-offset-*` colors, especially against dark backgrounds, for proper visibility and contrast.
**Action:** Always add `focus-within:opacity-100` to parents containing `opacity-0 group-hover:opacity-100` elements if they contain focusable actions. Include robust `focus-visible` styles with explicit offsets, and remember to hide decorative/icon SVGs from screen readers inside labeled buttons.
