## Invariants — properties future waves MUST preserve

These are the load-bearing contracts. If any wave breaks one, the wave failed.

1. **Audit log retention allowlist is fail-CLOSED.** `RETENTION_POLICIES` (wave 105) contains only operational actions. Adding an evidence action throws at module load. Never weaken this guard.
2. **PII redaction runs on every log call.** Two-tier policy (substring + exact) in `src/lib/logger.ts`. Don't bypass.
3. **CSRF/origin enforcement runs FIRST in `clerkMiddleware`.** Before auth lookup. Don't move it later in the chain.
4. **Webhook routes bypass CSRF via explicit prefix allowlist only.** Never substring-match; the substring approach (`pathname.includes('/webhook')`) created a Critical bypass in wave 107 that 107.1 hotfixed.
5. **`outboundFetch` is the only sanctioned outbound HTTP in API routes.** ESLint warns on bare `fetch()`. Codemod is wave 107.5.
6. **Kill-switch checkpoint inside every iterative tool loop.** `claudeToolUse` calls `budgetCheckpoint` per iteration. Any future tool-loop primitive must do the same.
7. **Memory ops skip `userId === "anon" || !userId`** in BOTH search and store. Cross-tenant namespace defense.
8. **`pastContextAsPrompt()` auto-prepends `PAST_MEMORY_DIRECTIVE`** in front of wrapped content. Don't strip the directive in a future "cleanup" PR — it closes the 140x prompt-injection-via-memory blast radius.
9. **`neutraliseInjectionPatterns()` runs before `storeMemory`** in the factory store hook. Layer-2 defense.
10. **`runWithBudgetAndAudit` captures stats INSIDE the budget scope.** Outside the scope, AsyncLocalStorage has torn down and `getExecutionStats()` returns null.
11. **Methodology scorers fail OPEN, never block delivery.** `craap()`, `sift()`, `finer()`, and `methodologyVerify()` set `degraded: true` on any error path (malformed JSON, NIM outage, kill-switch trip, empty input). They are AUDIT signals attached to the receipt envelope — using them as a hard gate would let a NIM degradation silently brick every regulated-vertical agent. Buyers asking for stricter behaviour must layer an explicit threshold check ON TOP of the result (`if (r.overall < 0.6 || r.degraded) hold-for-review`), never inside the scorers themselves.
12. **CRAAP / SIFT / FINER scorer prompts are FROZEN contracts.** The JSON shape each scorer expects from the model is exact: any model that returns a different shape lands in the degraded path. Future cleanup PRs MUST NOT "improve" the prompts without updating `tryParseJson` + `toDim` + `normaliseClaim` in lockstep and re-running the 27 contract tests. The frozen shape is what lets the receipt envelope validate the methodology layer without re-running it.

## Decision log — non-obvious choices made this session

- **Refused Modules 1-9 from the "master blueprint" prompts.** Multiple security vulnerabilities (command injection, hardcoded fallback secrets, path traversal) + fictional infrastructure (OpenClaw, NeMo Retriever, Matrix homeserver) + Vercel-incompatible patterns. Real systems already implement the intent correctly.
- **Wave 109 SKIPPED `for-recruiting`** even though it had the standard signature. The 3-line h1 + longer hero blurb structure didn't fit cleanly into the shell.
- **Wave 110 chose `competitor-scan` as the first multi-step conversion** over lead-blitz/closer because of clear tool boundaries, headline marketing position, and zero dependencies on voice infra.
- **Wave 111 chose `leads` as the first memory opt-in** because the memory pattern (compound past lead signals on same niche) has obvious user value vs other agents.
- **DNS-rebinding fix scope decision in wave 110.1**: per-caller defense in `fetch_page` only (the only NEW SSRF surface wave 110 added) rather than promoting to `outboundFetch` itself. The architectural fix is deferred to wave 107.2.
- **Per-user memory write cap deferred twice** (wave 110 + wave 111 reviews). Real gap. Track as H2 above. Don't defer a third time.
- **Wave 111.x ships H2 + H3 together** because both are surfaced by the same wave-107.2 review hand-off, both are <half-day each, and both add new lib modules whose tests live next to each other. Bundling avoids re-priming context twice.
- **H3 helper does not throw at module load.** Earlier draft considered a top-level throw when env is missing; rejected because it would brick every Next.js worker on Vercel just because of a missing optional env (auto-onboard is the only consumer, and it falls through to Clerk-only when the secret isn't configured). Instead `verifyInternalSecret` fails closed on every call + a one-shot production log surfaces the misconfig in observability.
- **H2 cap is 10K rows per user, not a 90-day TTL.** Two reasons: (a) trim happens lazily on insert — no cron required, no new operational surface; (b) IVFFlat recall degradation is row-count driven, not age driven, so a fixed-N policy is the right shape. M6 (retention-cron backstop) is left as a follow-up for the long tail of inactive users whose 10K rows still exist forever.
- **Wave 112 chose CRAAP + SIFT + FINER as the methodology baseline** over alternatives (e.g. RAGAS, TRiSM, FActScore) because the three frameworks are (a) primary-literature canonical with cited authors and known evaluator panels — the kind of provenance a regulator-facing receipt actually needs, (b) covers three orthogonal axes (source credibility / claim verification / hypothesis quality) so adding them is additive not redundant, (c) zero new dependencies — pure prompt-engineering against the existing NIM client. RAGAS would have added a Python dependency; FActScore would have required maintaining its own claim-decomposition model.
- **Wave 112 wires the methodology layer as opt-in only.** Default-off because ~1-2s latency per request matters for 140 agents most of which produce non-factual output (lead-scoring, ad-creative, email-sequence). The buyer who cares (regulated-vertical agency-packet, clinical-scribe, contract-analyzer) sets `runMethodology: true` explicitly — same pattern used by `useVerifier: true` and the memory hooks. Wave 112.1 will opt the regulated-vertical agents in route-by-route.
- **Wave 112 attaches to the existing `verifyOutput()` envelope rather than a separate post-flight pass.** Two reasons: (a) the methodology NIM calls run in parallel with `llamaGuardOutput()`'s NIM call, so the wall-clock cost is whichever is slower — not the sum; (b) keeps the receipt-envelope shape unchanged: one `VerificationResult` per agent execution with an optional `methodology` field, instead of two separate envelopes that the buyer's auditor would have to correlate by timestamp.
