## 2024-07-04 - ScreenNode and NoteNode Accessibility Improvements
**Learning:** For keyboard accessibility, it is essential to ensure that interactive elements which are hidden by default (e.g. `opacity-0` but shown on hover `group-hover:opacity-100`) also become visible when they receive focus via keyboard navigation. In standard TailwindCSS setup, using `focus-within:opacity-100` on the container or `focus-visible:opacity-100` on the element itself solves this. Furthermore, elements without visible text (like icon-only buttons) must have an `aria-label` attribute, and standardizing a clear focus ring using `focus-visible:ring-1` or similar helps a lot with visibility.
**Action:** Always check container structures for `opacity-0 group-hover:opacity-100` and append focus visibility fallbacks. Apply ARIA labels to buttons without text content.
