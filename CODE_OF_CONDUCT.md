# Code of Conduct

This is a small project right now. The Code of Conduct reflects that.
If we grow, we'll adopt a longer version (Contributor Covenant 2.1 is
the reference). Until then, the short rules below apply.

## Scope

This Code applies to anyone participating in the open zones of this
repository — issues, pull requests, discussions, the npm package's
issue tracker, and any chat or call related to contributing. It does
not apply to private exchanges between Sovereign Matrix and its
customers.

## Rules

1. **Be honest.** Don't claim work that isn't yours. Don't invent
   benchmarks or capabilities. If you're not sure, say so.

2. **Be specific.** "It doesn't work" is not a useful report.
   "Step X returns HTTP 500 with this stack trace" is. Maintainer time
   is the bottleneck — write reports that respect it.

3. **Be helpful.** If you're rejecting another contributor's PR, give
   them a path forward. If you can't, say what's missing.

4. **No personal attacks.** Critique code, decisions, and architecture
   freely and with evidence. Don't critique people. The line is "your
   PR introduces a SSRF" (fine) vs "you're a bad engineer" (not fine).

5. **No spam.** Don't open PRs or issues to promote a product, service,
   or yourself. Don't ping maintainers across multiple channels for
   the same item.

6. **No security disclosure in public.** See `SECURITY.md`. If you
   accidentally open a public issue about a vulnerability, the
   maintainers will close it without comment and ask you to email
   `security@sovereignmatrix.agency`. Don't take it personally — it's
   policy, not judgment.

7. **No commercial use of the proprietary zones** without permission.
   See `LICENSE`. Asking for permission is welcome and free; using
   without asking is not.

## What we do when someone breaks the rules

First offense: a maintainer messages you privately, explains the
specific rule, and gives you a chance to correct course.

Repeated or severe: the maintainer may close your PRs/issues without
review, block your GitHub account from the repository, and/or ban you
from related discussion channels.

We don't keep a public list of bans. We do keep notes so the second
offense isn't treated like the first.

## Reporting

For things that need maintainer attention — including conduct issues
between contributors that you've tried to resolve directly first —
email `spec@sovereignmatrix.agency`. Include screenshots, links, and
context. We treat reports as private.

## Maintainer commitments

The maintainer commits to:

- Apply this Code equally to themselves. If you think the maintainer
  has broken a rule, reply on the thread or email the address above
  — both are valid escalation paths.
- Respond to good-faith reports within 7 days.
- Not weaponize this Code against contributors whose technical
  positions they disagree with. Disagreement is allowed. Personal
  attacks aren't.

## Why this is short

Long Codes of Conduct serve communities that need them. This
community is currently 1 person + occasional drive-by contributors.
The short version above covers every situation we've actually
encountered. We'll lengthen it when we have to.

If you want the canonical long version that we'll adopt later,
see the [Contributor Covenant 2.1](https://www.contributor-covenant.org/version/2/1/code_of_conduct/).
